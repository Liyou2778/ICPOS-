## 2. 质证口径（被追问时怎么说）

### Q：你们的数字是模拟的，能说明什么？
**应答**：“是的，参赛 MVP 按‘模拟先行’策略（指导书 §5.2/PRD §4.2 范围外）以仿真数据验证算法与流程闭环。
模拟数据生成器按真实设备运行机理构造（温漂型故障前兆、车铲循环、道路拥堵系数等），
因此验证的是**机制与算法有效性**而非具体工况数字。真实设备 IoT 接入与模型迁移是我们 V1.1 的第一优先试点项。”

### Q：如何证明不是大模型‘编’出来的？（防幻觉）
**应答**：“三道防线：① 全部设备参数/价格/TCO/空载率等数字由结构化数据库直读计算，大模型只负责组织语言；
② 知识类回答强制携带引用来源（条目+版本），知识库外问题明确拒答转人工；
③ 所有生成内容标注‘AI 生成初稿，需人工确认’。可以现场演示任一数字与库内记录对账。”

### Q：为什么界面右上显示“离线演示模式”？
**应答**：“为保证现场网络不稳定的演示可靠性，默认无密钥离线运行：全流程与数字可用，仅自然语言组织由确定性模板完成；
评审如需看真实大模型行文，填入 API Key（DeepSeek/通义，双供应商容灾）即自动切换，路由与防幻觉机制不变。”

### Q：三个赛道方向融合会不会失焦？（R6）
**应答**：“我们刻意聚焦**矿山施工全流程闭环**一条主线（方案→调度→运维→交互），土方/农业仅保留知识库与界面扩展点。
答辩口径三份材料（文档/PPT/系统）已逐字统一。”

### Q：模拟数据从哪来？有没有合规问题？
**应答**：“设备参数取自徐工官网/产品手册等**公开渠道**，非关键参数已标注‘示例数据’；
工况时序由生成器构造，不含任何真实客户或设备隐私数据。所用开源依赖与数据来源已列入交付包《声明》。”

### Q：怎么证明算法效果而不是‘算出来好看’？
**应答**：“A/B 在同一数据集、同一评估脚本下运行（`/api/dispatch/ab`、`train_models` 设备留出法），
结果写入 `data/models/eval_report.json` 可复现；调度每条派单附可解释原因，全部结论需人工确认后下发（安全边界）。”

### Q：商业上谁买单？
**应答**：“制造商/施工企业/租赁商三类客户：SaaS 订阅 + 项目制部署 + AI 调用费 + 数据增值（详见 PRD §10），
以‘后市场服务价值释放’为最大市场空间（欧美成熟市场后市场贡献约 70% 利润）。”

任何答辩或宣传材料**不得**把照片识别、缺陷检测、视觉巡检计入已实现指标，

## 5. 真实企业案例验证（外部效度，2026-09 新增）

用 **4 个可溯源的公开案例**（需求 + 最终结果）检验方案智能体，而非自造数据自证：

| 案例 | 来源层级 | 需求 | 真实结果 |
|---|---|---|---|
| 国家电投白音华露天矿无人驾驶剥离（2025） | 官方媒体（中国能源报） | 年剥离 **806 万 m³** | **40 台**无人矿卡；日均 5.9 万 m³；22.5 h/日；出动率 ≥95% |
| 国家电投白音华四大剥离工程（2026—2030） | 行业媒体+二手 | 5 年、无人设备 **≥240 台** | 总标的 **78 亿元**；**271 台**；总工程量 8.88 亿 m³ |
| 平煤神马建工纯电矿卡采购 | 官方招标平台 | 75 吨级 **20 台**、限价 **2800 万** | 中标 **2600 万**（130~136 万元/台） |
| 国家能源集团液压挖掘机集采 | 官方招标平台 | 批量集采 | 雷沃 1799 万、**徐工矿业机械** 1845 万 |

**验证结果**：需求解析 **4/4**、配置校验 **2/2**、阻塞/放行 **4/4**、规模诚实性 **2/2**；
单车日产能 3,828 吨/台·日落在真实区间 **[1,568, 3,835]** 内（偏上沿，1.42×中值）；车铲比 6.3（经验区间 3~6，放宽 8）。

**验证中发现的缺陷（已修复并加回归测试）**：① "75 吨级"曾被当作工程量；② "总工程量 8.88 亿 m³"曾被当成年产量（高估 5 倍）；
③ 识别不到"最高限价/计划投资/合同额"等同义预算表述；④ 超规模需求曾静默输出 58 挖+366 车的巨型配置而无任何声明。

**必须如实披露的能力边界**：参数库单价为示例数据，与真实成交价相差约 **3 倍**；参数库仅覆盖中小型露天矿，
对 4.6 亿吨/年矿区不具备配置能力；无人驾驶/纯电装备不在参数库内；**验证集仅 4 个案例，只能证明"未犯明显错误"，
不能证明"普遍准确"**。完整报告见 [`docs/validation/agent_real_case_validation.md`](../validation/agent_real_case_validation.md)。

**总量口径**：pytest **68 项全绿**；ruff check/format 通过；前端 tsc + eslint + build 通过；
`data/models/corpus/eval_report.json`（语料模型 P1：检出 10/10、提前量 24.3h、部件 Top1 90%、误报 2.0%）；
`data/models/project/eval_report.json`（项目运营模型未过门控 + 标定基准）。

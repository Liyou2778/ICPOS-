# 项目运营分析方法与数据边界（可质证版）

> 面向评审质询：本项目在"工程项目运营"方向上做了什么、凭什么结论可信、哪些话不能说。
> 所有数字均可在本仓库复现（命令见文末），不存在仅在 PPT 中出现的指标。

## 一、数据来源与真实性分级

| 数据类型 | 条数 | 真实性 | 来源/生成方式 |
|---|---|---|---|
| `project_budget` 招标锚点 | 27 条记录 → 去重 **22 个项目** | **真实（real）** | 内蒙古自治区公共资源交易网等公开招标/中标公告；含招标人、行业、地区、交易平台、公告日期、计划总投资、标段预算合计、中标金额、计划工期、资金来源、批复单位、公告链接 |
| `construction_task` 施工任务 | **340 条** | 仿真（simulated） | 按上述真实锚点（工期/规模/工序口径）仿真生成：穿孔凿岩/爆破/铲装/运输/排土五道工序、循环、计划与实际排期、工作量、班组、设备、状态 |
| `actual_cost` 成本台账 | **385 条** | 仿真（simulated） | 按锚点标段预算与工期仿真生成，分人工/材料/机械/其他/管理五类，合计 **57,069.5 万元** |

**划分**：数据源按项目划分 train（11 项目）/ test（11 项目），**零交叉**（`project_manifest.json.overlap_projects = []`），
从源头保证评估不泄漏。血缘清单记录两份文件的 SHA-256、行数、类型分布、跨文件重复数（0 条）。

## 二、数据治理（可复算）

- ETL：`scripts/ingest_project_corpus.py --strict`（校验 → 去重 → 字段规范化 → 幂等 upsert → 血缘清单）。
- **幂等性可被测试证明**：`backend/tests/test_project_corpus_etl.py` 连续执行三次 ETL，断言
  新增记录为 0、无重复键（项目编号/任务编码/台账幂等键）、且**库内状态指纹逐位一致**。
  说明：ETL 是"收敛式 upsert"（重跑会刷新字段），因此"updated 计数非零"是预期行为，
  真正的幂等标准是**状态可复现且不膨胀**。
- 规范化校验：金额单位为元、日期 `YYYY-MM-DD`、成本类型限定五枚举、工作量与单位合法、计划完工 ≥ 计划开工、
  台账必属真实项目。

## 三、建模与评估协议（防泄漏）

- **特征仅取计划侧信息**：工序、阶段、循环、计划工期、工作量与单位、班组、设备数量、项目规模、计划月份。
- **严禁使用** `actual_start` / `actual_end` / `status` / `progress` 作为特征（标签来源）——
  该约束由 `test_project_models.py::test_no_label_leakage_in_features` 自动扫描守住。
- 训练仅用 train 项目；训练集内做 **Leave-One-Project-Out** 交叉验证并报 95% 置信区间；
  独立 test 项目**仅最终评估一次**、阈值固定不调参；全部指标与**朴素基线**对照。

## 四、评估结论（如实呈现，含"没有做出可用模型"）

| 模型 | 指标（独立测试集） | 朴素基线 | 结论 |
|---|---|---|---|
| 任务工期偏差（回归） | MAE **2.248 天**、RMSE 3.454 天、R² **-0.488**；LOPO MAE 2.570 天（95%CI 1.606~3.533） | 中位数基线 MAE **1.127 天** | **未跑赢基线** |
| 任务工期偏差（三分类） | 准确率 0.841、macro-F1 0.540 | 多数类基线 **0.841** | **无增益** |
| 项目成本构成（五类占比） | LOPO MAPE **23.91%** | 全局均值基线 **14.73%** | **未跑赢基线** |

**可学习性取证**（`scripts/diagnose_project_signal.py`）：

- 训练集 R² 0.9988，而 5 折 CV R² ≈ **-1.98** ⇒ 模型只记住了噪声；
- 单特征与偏差的最大相关系数 **|r| = 0.12**（远低于可利用阈值 0.3）；
- 工序组间方差占比 eta² = **0.042** ⇒ 工序几乎不解释偏差；
- 偏差分布 P50 = 0、P75 = 0、P90 = 3 天、类别 108 准时 / 18 延期（无"提前"类）。

结论：**该语料的延期标签为噪声生成（按锚点叠加扰动），不含可泛化信号**。
这不是建模能力问题，而是数据本身的性质——诚实披露比包装成"AI 预测"更有价值。

## 五、上线门控（自动、可审计、防事后手改）

`deploy_decision.ml_deployed` 仅在同时满足
①测试集 MAE < 基线 MAE，②LOPO MAE 95% 置信区间上界 < 基线 MAE 时为真。
本次两项均不满足 ⇒ **ml_deployed = false**，生产方法记为 `calibrated_statistical_baseline`，
ML 产物（`task_delay_reg.joblib`/`task_delay_clf.joblib`）保留供审计但不参与生产输出。

`test_project_models.py::test_deploy_gate_is_consistent_with_evidence` 会重新推导门控结论并与报告比对，
任何"只改结论不改证据"的修改都会导致测试失败。

## 六、生产方案（标定统计基准，明确不是 ML 预测）

| 能力 | 方法 | 输出（实测标定） |
|---|---|---|
| 工序交期缓冲 | 历史偏差分位数（按工序分列，样本 <8 不单列） | P80 **1 天**、P90 **3 天**（P80 作为缓冲建议） |
| 成本结构校核 | 五类占比基准 + P25~P75 容差带 | 机械 36.9% / 材料 29.8% / 人工 17.2% / 管理 8.8% / 其他 7.4%；越界提示结构偏差 |
| 预算执行预警 | 合同额/标段预算分位数 | P25 0.900 / P50 0.950 / **P75 1.105（预警）** / **P90 1.175（严重偏差）** |
| 成本结构测算 | 基准结构 × 预算执行比率分位数 | 期望值 + 合理区间 + P90 不利情形，逐类给出金额区间 |

每一条接口输出都携带 `method`（明示"标定基准法，非 ML 预测"）、`basis`（口径）、`disclaimer`（需人工复核）
与样本量；前端「项目运营分析」页同时展示评估报告与数据边界警示。

## 七、数据边界与禁止性表述

1. 施工任务与成本台账是**仿真数据**，不是真实施工记录；引用必须同时说明，不得混同为真实台账。
2. 样本量小（已完工可标注任务 126 条 / 项目 20 个 / 台账 385 条），置信区间宽，**不可外推为行业规律**。
3. 禁止表述："AI 预测工期"、"AI 预测成本/超支概率"——模型未通过门控；
   正确表述："基于历史偏差分位数的缓冲建议"、"基于历史结构占比与预算执行区间的成本参考"。
4. 招标锚点可对外引用（公开公告，附来源链接）；仿真部分对外一律标注"仿真生成"。
5. 所有输出定位为**决策参考**，需造价/计划人员确认，不替代合同与造价审核。

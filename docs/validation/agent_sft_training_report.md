# Agent SFT（QLoRA）训练与微调前后评测报告

> 结论先行：**微调使"拒答正确率"从 0.50 提升到 1.00，但把"数字命中率"从 0.895 打到 0.632**，
> 属于"学过头"的过度拒答。依据与项目其它模型一致的上线纪律，**该 adapter 门控关闭、不上线**；
> 生产配置维持「基座模型 + 已修复的检索」。根因已定位到**训练集与评测集的类别分布错配**，修复方案见 §6。

## 1. 训练配置（实测，可复现）

| 项 | 值 |
|---|---|
| 硬件 | NVIDIA RTX 4060 Laptop **8 GB**（另有 Unity/浏览器占用 3~4 GB） |
| 基座 | `Qwen/Qwen2.5-1.5B-Instruct`（3.09 GB 权重，经 **hf-mirror** 下载；直连 huggingface.co 本机不可达） |
| 方法 | **4-bit QLoRA**（bitsandbytes nf4 + double quant）→ LoRA r=16, alpha=32, dropout=0.05，7 个投影层 |
| 依赖 | `torch 2.14.0+cu126`、`transformers 5.17`、`peft 0.21`、`datasets 5.0.1`、`accelerate`、`bitsandbytes 0.50`（uv 安装） |
| 超参 | max_len **512**、batch 1 × 梯度累积 8（等效 8）、lr 1e-4、cosine、warmup 50 步、1 epoch、梯度检查点 |
| 数据 | `data/sft/agent_sft_train.jsonl` **5852 条**（含 532 条拒答负样本） |
| 结果 | **train_loss 2.294 → 0.386**；可训练参数 **18,464,768**（LoRA）；基座参数量 ≈1.65 B |
| 耗时 | **3405 s（57 分钟）**，1.72 样本/秒；每 50 步保存检查点（会话中断可续训） |
| 产物 | `data/models/agent_sft/adapter/`（70.5 MB）、`train_log.json`、`train_stdout.log` |

> 工程备注：transformers 5.x 移除了 `TrainingArguments.warmup_ratio`（改用 `warmup_steps`）；
> 4-bit 量化下 `parameters()` 的 numel 是**打包存储单元数**（907M），不能当参数量对外报，
> 脚本改为按 config 估算真实参数量并单独标注。

## 2. 评测协议（防自证）

- **检索上界基线**：把检索到的【资料】原样当答案打分（`--dry-run`），用于回答"就算模型完美，能命中多少"；
- **基座**：`--tag base`；**微调后**：`--tag lora --adapter ...`；三者使用**同一批 60 条样本**（固定随机种子）；
- 指标：数字命中率（期望答案中的关键数字在生成答案中的覆盖比例）、字符 bigram F1、
  **拒答正确率**（资料不含答案时明确拒答的比例）、**正样本误拒率**（可答问题被拒答的比例）；
- 评测集 `evaluation_qa` 756 条**不参与训练、也不进知识库**（`test_eval_questions_not_in_training_set`、
  `test_evaluation_qa_not_indexed_into_kb` 两道门禁）。

## 3. 微调前后结果（同一批 60 条，实测）

| 指标 | 检索上界 | 基座 | 微调后 | 微调 Δ |
|---|---|---|---|---|
| 样本 | 54 正 / 6 负 | 54 / 6 | 54 / 6 | — |
| **数字命中率** | 0.8947 | **0.8947** | **0.6316** | **-0.2631** ❌ |
| 数字全命中率 | 0.8947 | 0.8947 | 0.6316 | -0.2631 |
| 字符 bigram F1 | 0.1687 | **0.2784** | 0.1933 | -0.0851 |
| **拒答正确率** | 0.0000 | 0.5000 | **1.0000** | **+0.5000** ✅ |
| 正样本误拒率 | 0.0000 | 0.0556 | **0.3519** | **+0.2963** ❌ |

按类别拆解（更能说明问题）：

| 类别 | n | 基座命中 | 微调命中 | 基座拒答率 | 微调拒答率 |
|---|---|---|---|---|---|
| fault_case | 48 | **1.000** | 0.750 | 2.1% | **29.2%** |
| equipment | 2 | 1.000 | 0.000 | 0% | 50% |
| maintenance | 6 | 0.000 | 0.000 | 33% | 100% |
| data_dictionary | 3 | 0.000 | 0.000 | 67% | 100% |

**读法**：微调确实学到了"资料不足要拒答"（负样本 6/6 全拒），但同时把**可答的故障码问题也拒掉了近三成**，
而故障码问答正是评测集的主力类别（48/60）。基座模型在检索修复后已经能命中 0.895（等于检索上界），
微调反而把它拉回了修复前水平。

## 4. 根因诊断（有证据，不是猜）

1. **训练集与评测集类别错配**：训练集 85% 是 `proj_operation`（项目编号/工期成本查询，5000/5852），
   而评测集 71% 是 `fault_case`（故障码问答，48/60）；训练集中 fault_case 正样本仅 **210 条**。
2. **拒答负样本比例过高**：532 条（占 9.1%）vs fault_case 正样本 210 条 → 模型把"不确定就拒答"泛化过头；
   且负样本是"问题与资料完全不相关"，模型学到的是粗粒度触发条件，而非"所问实体是否在资料中"。
3. **长度截断**：max_len 512（为 8 GB 显存压缩），部分样本的检索资料被截断，进一步推动"证据不足→拒答"。
4. 交叉验证：同一批误拒样本中，**基座也拒答的只有 3/19**，说明不是检索质量退化（检索代码与 KB 在两次评测间未变，
   数字命中率 0.8947 的检索上界也未变）。

## 5. 上线门控决策

| 候选 | 判定 | 理由 |
|---|---|---|
| 微调 adapter | **不上线**（`deployed=false`） | 主指标（数字命中率）显著劣化 0.895→0.632，正样本误拒率 35% |
| 基座 + 已修复检索 | **生产配置** | 数字命中率 0.895（= 检索上界）、bigram F1 0.278、拒答正确率 0.50 |

这与本项目其它模型的处置一致：**能证明"模型不行并且不上线"，比上一个好看的指标更有价值**。
adapter 保留在 `data/models/agent_sft/adapter/`，可随时用于回归对比。

## 6. 修复方案（下一步，按性价比排序）

| 优先级 | 动作 | 预期 |
|---|---|---|
| P0 | **平衡类别**：`proj_operation` 从 5000 降到 ~1000，fault_case 正样本扩到 ~600（每案例 3~4 种问法） | 让训练分布贴近实际问答分布 |
| P0 | **拒答负样本降到 3~4%**，且改为"近邻缺失"（同类别相邻故障码不在资料中）而非完全不相关 | 教"按所问实体判断"而不是"拿不准就拒" |
| P1 | 加入"资料中包含答案但表述不同"的正样本（改写问法/同义表述） | 抑制过度拒答 |
| P1 | max_len 恢复到 768~1024（需关闭 Unity 等释放显存） | 减少证据被截断 |
| P2 | 引入分类别评测权重 + 每类最小样本量门槛，纳入 CI | 防止"总体指标掩盖单类别塌陷" |

## 7. 局限与数据边界（必须随报告声明）

1. **评测集与训练集同源**：`evaluation_qa` 与训练样本都来自同一批结构化语料（不同问法），
   因此分数只能说明"事实一致性与格式合规"，**不能说明泛化能力**；外部评测集（真实招标案例 5 条）另行使用。
2. **检索上界 0.895 是硬约束**：期望答案中的数字有 10.5% 不在检索资料中（知识覆盖缺口，如徐工官网解决方案页未入索引），
   任何模型都无法命中这部分——因此"数字命中率 1.0"不是合理目标。
3. **单次运行、单批样本（60 条）**：结论置信区间较宽，类别样本量小（equipment 仅 2 条），
   不应据此对"微调"下普遍性结论，只能说"本次配置下微调劣化了主指标"。
4. **训练数据全部由确定性模板生成，不含人工标注**：只能教"接地事实表达与拒答行为"，不能教推理能力。
5. **数据边界**：设备型号规格为真实公开产品页数据；价格/TCO、故障案例、项目运营、客户与合同为仿真构造。

## 8. 复现命令

```powershell
# 数据与评测集
.\.venv\Scripts\python.exe -m scripts.build_sft_dataset
# 微调（8GB 显存：max_len 512 + 4-bit QLoRA；中断后可自动断点续训）
.\.venv\Scripts\python.exe -m scripts.train_agent_sft --epochs 1 --max-len 512 --save-steps 50
# 三方对比评测（检索上界 / 基座 / 微调后）
.\.venv\Scripts\python.exe -m scripts.eval_agent_sft --dry-run --tag retrieval_only_v3 --limit 60
.\.venv\Scripts\python.exe -m scripts.eval_agent_sft --tag base --limit 60
.\.venv\Scripts\python.exe -m scripts.eval_agent_sft --tag lora --limit 60 --adapter data\models\agent_sft\adapter
```

产物：`data/models/agent_sft/{adapter/,train_log.json,eval_base.json,eval_lora.json,eval_retrieval_only_v3.json}`。
